# pdfapi — фронтенд

Next.js 15 (App Router) + Tailwind 4. Лендинг, документация, аутентификация,
кабинет. Светлая и тёмная тема с ручным переключателем.

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000
```

Ваш Fastify должен крутиться на 3001. Если порт другой:

```bash
API_ORIGIN=http://localhost:3001 npm run dev
```

## Как связаны фронт и API

Браузер ходит **только** на `localhost:3000`. Запросы вида `/api/auth/login`
Next переписывает на `http://localhost:3001/auth/login` (см. `next.config.ts`).

Это сделано намеренно: для браузера всё выглядит одним источником, поэтому

- не нужен CORS на бэкенде,
- сессионная кука с `SameSite=Lax` отправляется без настроек,
- в проде достаточно поменять одну переменную окружения.

```
браузер ──► Next :3000 ──► /api/* переписывается ──► Fastify :3001
```

## Что нужно на стороне бэкенда

1. `conf.isProd` — исправьте опечатку `producrion` → `production`, иначе
   в проде кука уедет без флага `Secure`.
2. `resetTokenTtl` и `appUrl` должны быть в конфиге.
3. Ссылка в письме сброса должна вести на `${appUrl}/reset?token=...`
   (страница фронта), а не на `/auth/reset` (эндпоинт API).
4. Ссылка подтверждения — на `${appUrl}/verify?token=...`.

## Производительность анимаций

Всё построено на двух правилах, и они соблюдаются везде:

**Анимируются только `transform` и `opacity`.** Эти свойства браузер считает
на GPU, не пересчитывая раскладку. Поэтому полоса квоты растёт через
`scaleX`, а не `width`; мобильное меню и подложка переключателя темы ездят
трансформом; кнопки нажимаются через `scale`.

**Появление по скроллу — `IntersectionObserver`, не слушатель `scroll`.**
Слушатель срабатывает десятки раз в секунду и считает геометрию для каждого
элемента. Наблюдатель сообщает о пересечении сам, вне главного потока, и
отключается после первого срабатывания.

Плюс:

- `prefers-reduced-motion` отключает всё движение — это не любезность,
  а требование доступности;
- нет ни одной анимационной библиотеки (framer-motion и подобные весят
  30–50 КБ ради того, что здесь делает CSS);
- подсветка кода своя, 40 строк вместо highlight.js на 90 КБ;
- иконки — инлайн-SVG, ни одного шрифта иконок и ни одного запроса.

Итог сборки: **113 КБ JS** на лендинге, все страницы пререндерятся статически.

## Тема

Три состояния, а не два: светлая, тёмная, системная. Системная — не то же
самое, что светлая: она следует за настройкой телефона, который вечером сам
переключается.

Токены живут в `globals.css`. Ни один цвет не определён только внутри
`@media (prefers-color-scheme)` — иначе при ручном переключении часть палитры
осталась бы от другой темы. Скрипт в `<head>` ставит атрибут до первой
отрисовки, чтобы страница не мигала светлой.

## Структура

```
src/
  app/
    layout.tsx          корневой каркас, провайдер темы, метаданные
    globals.css         токены, анимации, доступность
    page.tsx            лендинг
    docs/page.tsx       документация
    login/page.tsx      вход
    register/page.tsx   регистрация
    verify/page.tsx     подтверждение почты
    forgot/page.tsx     запрос сброса
    reset/page.tsx      новый пароль
    dashboard/
      layout.tsx        охрана маршрута + шапка кабинета
      page.tsx          квота, выпуск и отзыв ключей
  components/
    theme.tsx           провайдер темы + скрипт против мигания
    theme-toggle.tsx    переключатель на три положения
    ui.tsx              Button, Input, Card, Badge, Toast, Skeleton, Reveal
    header.tsx          шапка сайта
    footer.tsx          подвал
    auth-shell.tsx      каркас страниц входа
    hero-demo.tsx       анимация «команда → PDF»
    code-block.tsx      блок кода с подсветкой и копированием
    docs-nav.tsx        боковая навигация документации
  hooks/
    use-session.ts      кто сейчас в браузере
  lib/
    api.ts              обёртка над fetch, типы, тексты ошибок
```

## Чего пока нет

- **Админки** — по вашему решению отложена.
- **Живого демо на лендинге** — сейчас анимация нарисованная. Подключается
  к `/v1/convert` с демо-ключом и жёстким лимитом по IP.
- **Оплаты** — появится вместе с биллингом на бэкенде.
- **Тестов** — для фронта достаточно Playwright на три сценария: регистрация,
  вход, выпуск ключа.
